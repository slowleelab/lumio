## 0. 结论摘要（TL;DR）

1. **现状不是一个 bug，而是一个"层次没分开"的架构问题**：噪声判定、闲聊判定、多轮语境判定被散落在正则、词表、模板、slice 置信度门里，各自为政，且**绕过了本应承担主判定责任的上下文感知模型**。
2. **系统不是从零开始**：已有上下文感知 BERT（吃 history）、规则型 DST 雏形（`slot_tracker` 跨轮 Redis 持久化 + `missing_required`）、会话状态（`SessionState.entity_pool/intent_stack/pending_action`）、四步闭环开关（`closed_loop.json`）、黄金评测框架（`test_golden_eval.py`）、回流感知缝（`trap_collector.py`）。**方案是"把这些资产接到正确的位置"，不是重写。**
3. **核心架构判断**：以**上下文感知模型为主干**（判"这句在前文里想干嘛"），以**确定性状态为兜底**（判"上文在等什么、填没填上"），以 **energy/OOD 认知校验提纯模型"认不认"**。噪声/闲聊的最终判定是"多信号投票 + 温和澄清"，绝不是外围正则第一刀。
4. **止损优先**：P0 最小侵入即可修复"上轮问卡号后四位、本句回 4444 被误判噪声"这条真实链路，且不破坏"先问候再乱打 hjfw"的防乱答初衷。
5. 落点全部接现有机制：`decision_log` 留痕、`CLS_`/`closed_loop.json` 配置、`test_golden_eval.py` 固化、`trap_collector.py` 回流。

### 1.2 关键问题（按严重度）

**P0 — 判定只看当前句、不看前文，且排最前**（多轮误杀根因）
- `bot_agent.py:449`（knowledge）与 `:984`（fallback）两处噪声门都是 `_is_noise_input(user_input)`，**只吃当前句字符串**，是硬性 OR、且排在感知历史的 grounding 门（:473）之前。
- 后果：上轮 bot 问"卡号后四位"，本句 `4444` → `_is_noise_input` 命中纯数字 → :457 直接回澄清"您的意思我还没太理解"，**走不到** `_has_grounding`、也走不到正常挂失流程。
- 反向洞：若简单改成"前面聊过就不判噪声"，会重开"先问候再乱打 hjfw"的乱答洞（该门的设计初衷，:443 注释明示"刻意不感知历史"）。**故不能用"有 grounding 就放行"一刀切。**

**P1 — 模型"认不认"用裸 softmax 置信度，校准弱**
- 根因证据：`_is_noise_input` 存在正是因为 BERT 会把纯数字**高置信**误判成闲聊/FAQ（:449 注释、fallback :982-983 注释）。说明 `primary_confidence` 过度自信，不能单独当"认不认"的闸。
- 叠加：history 是分布外拼接输入（若模型单句训练），置信度进一步失真。

**P1 — DST 槽位状态只在 knowledge 路径初始化**
- `_load_slot_prompt`（:1487）全文件仅 :440 一处调用，而 `_handle_business`（含 `CARD_LOSS`=挂失，`INTENT_DOMAINS` 归 business）不建 tracker。
- 后果：**"挂失时问卡号后四位、客户答 4444"** 这个最典型的 DST 场景，`missing_required` 为空，状态兜底落空。

**P2 — 无显式 OOS/噪声类**
- BERT 是闭合 10 类（`bert_classifier.py:32`），没有"上下文里我认不出来"这个输出。它只能押 softmax，无法结构化表达 OOD。这是把闲聊/噪声判成与业务意图同质的深层原因。

**P2 — 无统一"回话"判定概念**
- 多轮里"是不是回上文的话"（指代、确认、填槽、纠错）没有统一建模，散在 `_is_noise_input`、`_has_grounding`、`_is_uncertain_intent`、模板里。

### 1.3 架构判断：主次倒置 vs 分层

现在架构里，**确定性外围（正则、词表、模板）在前且互相独立，模型（上下文感知 BERT）只作其中一个 fast path，且其"认不认"能力没有被结构化使用**。这是"主次倒置"。

修正的架构原则：
- **模型是主干**，"这句在前文里想干嘛"由带上下文的 BERT 判；
- **状态是兜底**，"上文在等什么、填没填上"由规则型 DST 判（确定性、可解释）；
- **energy 校验是提纯**，把模型"认不认"从不可靠的 softmax 里分离出来（现成 logits，几乎不重训）；
- **外围输入闸降级为信号**，不再当独立判定层。

## 2. 目标架构（分层）

```
用户输入
  │
  ▼
L0 确定性社交（问候/告别/固定话术）── 精确匹配直出，不过模型  [bot/input_guard 同范式]
  │
  ▼
L1 上下文意图分类（主轴）── BERT(text+history) → (intent, conf, entities, alternatives)
  │        │  [A1]  用于判"这句在前文里想干嘛"，替代裸判噪声
  ▼        ▼
L1.5 认知校验（认不认）── energy = -logsumexp(logits)（现成 logits）→ {认/模糊/不认}  [A2]
  │        │  替代裸 softmax 置信度作为"认不认"闸
  ▼        ▼
L3 状态兜底（确定性）── slot_tracker.missing_required + pending_action + 本轮 entities  [A3,A4]
  │        判"上文在等什么、填没填上"；能量欠/不认时才强判
  ▼
L2 输入噪声信号（字符惊讶度，中英分脚本）── 只作投票之一，不是第一刀  [P2]
  │
  ▼
L4 多信号裁决
      ├─ 一致且确定 → 放行 / 拒绝
      └─ 落在模糊带宽 → 交 L5 仲裁
L5 模糊带宽仲裁（LLM，决策兜底）
      带上下文交 LLM 判 {业务|闲聊|噪声}；与证据链(energy/状态/惊讶度)投票，
      LLM"自信"仅作弱信号，不作通过依据；仍不一致 → 回 CLARIFY_RESPONSE（可恢复）
```

分层归属：
- **L0**：`input_guard.py` 同范式（确定性、免费）。
- **L1**：复用现成 `classify(history=)`。
- **L1.5**：新增 `OODScore`（`-logsumexp(logits)`），读 `bert_classifier` 暴露的 logits；不重训时先用 energy，重训路线走显式 OOS 类（与意图分类「域级×域内」两段式规划同轨，见《意图分类_SOP_拆解设计》draft-0.3）。
- **L3**：复用/补全 `slot_tracker`；关键改造是**把槽位状态机初始化上移到 `run()`**（domain 分派之前统一建/读），治好 business 路径 gap（1.2 P1）。
- **L2/L4**：收敛为独立组件 `InputGate`（仿 `input_guard` 范式），对外一个接口 `evaluate(...) -> GateVerdict{kind, confidence, reasons[], signals{}}`。
- **L5**：**分类兜底**用现成 `LLMClassifier` 慢路径（置信 < 0.7 时）；**决策兜底**在"模糊带宽"新增 LLM 仲裁调用（带上下文判 `{业务|闲聊|噪声}`）。结论仍以证据链(energy/状态/惊讶度)为准，LLM 自评置信不强断（对齐 `2306.13063`/`2311.00681`，调研发 OOD 上过自信）。

## 3. 分阶段落地技术方案

### P0 — 止血（最小侵入，修复"4444 被误判噪声"，可灰度）

**改动面**（2 文件为主，不动模型）：
1. **槽位状态机上移**：新建/抽取读逻辑 `_missing_required_slots(session_id)`，从 Redis `lumio:slot:{session_id}` 反序列化 `SlotTracker` 返回 `[(name,label)]`；在 `run()` 的 domain 分派前调用一次，保证 knowledge **和** business（挂失）都拿得到 `missing_required`。修复 1.2 P1-DST-gap。
   - 涉及：新增方法 + 把 `_load_slot_prompt` 的 tracker 读写抽成可复用的 `slot_tracker` IO 工具函数。
2. **噪声门改为"先判回话，再判噪声"**：`_handle_knowledge:447-450` 与 `_handle_fallback:984` 两处，把条件收紧为
   ```
   conf < CLARIFY_FLOOR
   or ( _is_noise_input(user_input)
        and not _is_replying_to_context(user_input, entities, missing_slots) )
   ```
   其中 `_is_replying_to_context`：`missing_slots` 非空时，本句抽到实体命中缺的槽（`_ENTITY_TO_SLOT`）、或纯数字/确认词匹配缺的槽（如 `card_tail`↔4 位纯数字）→ 判定回话，放行。
   - 关键：**没有简单用"有 grounding 就放行"**，而是"缺必填槽 + 本句填上了"才算回话，因此不重开"先问候再乱打 hjfw"的洞（hjfw 不填任何槽）。修复 1.2 P0。
   - **补充（2026-08-25，会话 b561cd04 复盘）**：缺槽之外还有一类"回话"——bot 自由反问（"需要帮助查询吗？"）后用户回确认词（"是的"），无缺槽、无 pending_action，此前被低置信门澄清成死胡同。已加 `_last_bot_turn_asked` + `_is_confirm_after_question`：无缺槽时若上轮 bot 以问句收尾且本句是确认词 → 轻量跟进话术（`confirm_followup`），不进澄清/检索；有缺槽仍走原回话豁免。同一批还把知识路径的噪声门评估提到 `_retrieve` 之前（低置信/分歧输入不再白付 RAG 检索）。测试固化在 `tests/test_confirm_followup.py`。
3. **判定留痕**：给 `DecisionAction` 加 `NOISE_BLOCKED` / `CONTEXT_REPLY_PASS`，用现成 `log_decision` 记录证据（conf、缺的槽、是否填上）。对齐 1.1 A9。
4. **黄金用例**：在 `test_golden_eval.py` 扩展一层"rephrase/context"用例，固化真值：
   - `4444`@上轮问卡号 → 期望 PASS（回话）
   - `hjfw`@有前文 → 期望 BLOCK（噪声）
   - `22元`@无前文 → 期望 PASS（带金额实体/槽位）
   - 中英乱码、指代（`第二笔`）、确认词（`嗯对`）各一条。
   防回潮。对齐 A8。
5. **配置开关**：以上"回话判定是否开启、噪声阈值"放 `GuardrailSettings`/`ClassificationSettings`（`CLS_` 前缀），并受 `closed_loop.json` 的 `guard_enabled` 类开关控制，支持线上"先只记不改判"灰度。对齐 A7/A11。
6. **灰度协议**：先线上"记但不拦"若干天，用 `decision_log` 的 `NOISE_BLOCKED` 对账真实误伤，再决定打开拦截。

**验收**：`4444` 链路不再误判；`hjfw` 仍拦；`pytest agent/tests/test_golden_eval.py` 全绿。

### P1 — 提纯"认不认"（校准 + OOD 打分）

1. **energy 认知校验**：`bert_classifier` 增加 `ood_score(text, history) -> float`（内部 `-logsumexp(logits)`，logits 现成 :147）。用于 L1.5，输出 `{认/模糊/不认}`，替代裸 softmax 作为"认不认"闸。几乎不重训，只需一个验证集标定阈值。
2. **校准**：温度缩放（小验证集上一维标量）把置信度校准到与准确率匹配；训练侧配合 label smoothing（Neural Collapse 效应会压缩特征、利于后续距离/OOD 打分）。
3. **golden 扩展**：把"上下文里不合法的话"（前文聊卡、本句 `hjfw`）作为 OOD 真值加入 intent 层。
4. **配置**：energy 阈值、校准温度纳入配置。
5. **LLM 模糊带宽仲裁（新增决策兜底）**：区分"分类兜底（现有 slow path）"与"决策仲裁（新增）"。当多信号落在模糊带宽（energy 中段、BERT 置信中段、L3 无铁证、惊讶度中性）时，把原文（可拼 history）交 `LLMClassifier` 判 `{业务|闲聊|噪声}`，与证据链投票；LLM 结果不单独作通过依据，自评置信视为弱信号；仍不一致 → 保守澄清。对齐 `2507.01541`。

### P2 — 中英多信号噪声闸（多语言、多信号）

1. **字符级惊讶度信号（中英分模型 + 脚本切分）**：分别用中文（单字 n-gram）与英文（字母 n-gram）建惊讶度模型；输入先按 Unicode 切中/英段，各段用对应模型打分，**任一段正常即放行**，避免误杀 `Visa`/`refund`/`bill`/`ATM` 与 `"refund 到没"` 混写。
2. **信号机制**：把惊讶度作为 `InputGate` 的一个信号（不是独立裁决）。已知边界：**重复数字 `444444` 惊讶度过低会漏抓**、**带语义数字 `22元`/卡号不能当噪声** —— 分别由槽位确认与实体信号兜住。
3. **统一 `InputGate` 组件**：仿 `input_guard`，对外 `evaluate(...) -> GateVerdict`，内部 = 惊讶度(中/英) + 上下文意图(conf) + energy 认知 + 状态(missing/slot) 多信号投票；阈值配置化；组件自身异常**统一回"放行"**并记 WARN（宁可退化成不拦，也不让闸门故障断业务）。
4. **golden 扩展**：乱码/中英混写/重复数字/带语义数字的格线真值全部入 golden。

### P3 — 数据驱动闭环

1. **误杀回流**：`trap_collector.py` 感知缝已存在（A10），接入——放行(`CONTEXT_REPLY_PASS`)后用户又**澄清/重问**的样本打"疑似误杀"标记；人工/半自动复核后归因（是哪个信号错了），回灌 `seed_dataset.json` 与闸门调参。
2. **与 `closed_loop.json` 四步闭环打通**：感知(trap)→评估(golden)→归因(decision_log 证据)→优化(重训/调参)，全链路闭环。
3. **定期评审**：`decision_log` 按 `NOISE_BLOCKED/CONTEXT_REPLY_PASS` 分组出报表，误杀率趋势纳入评审。

## 4. 横切关注点

- **可观测**：每次 `Gate` 判定写 `log_decision`（A9），证据含四信号分数 + 命中理由，可监管审计、可复盘误杀。
- **配置**：阈值/豁免/开关走 `CLS_`/`GuardrailSettings`/`closed_loop.json`（A7/A11），按环境可灰度、可逃生舱关闭。
- **评测**：所有真值入 `test_golden_eval.py`（A8），CI 每次提交跑，防回潮。
- **安全/合规**：`card_loss/complaint/transfer_agent` 等敏感类与"多信号判定"之间，沿用现有 `in {集合}` 合规底线；InputGate 判定不得压低敏感意图的转人工优先级（crisis/urgent 先于一切）。
- **容错**：InputGate 与惊讶度模型任何异常 → 保守放行（不拦），记 WARN；不阻断主线。
- **语言**：P2 前必须保证英文正常词（Visa/refund/bill/ATM）与中英混写不被误伤（脚本切分 + 分模型）。

## 5. 决策权衡与取舍

| 决策点 | 推荐 | 理由 / 代价 |
|---|---|---|
| 先 energy 还是直接训 OOS 类？ | 先 energy（P1），OOS 类（与意图分类两段式规划同轨）放后续 | energy 现成 logits、几乎不重训、成本低；OOS 类要重训、但更准 |
| "回话"判定用什么？ | 状态兜底（missing 槽 + 本句填充）为主，词表为弱信号 | 状态是铁证、可解释；词表只能叠加强信号，不能当判定本身 |
| 噪声哨能不能当第一刀？ | 不能，降级为信号 | 它会误杀带语义数字/英文；第一刀应是上下文意图（L1） |
| 有 grounding 就放行？ | 不，必须"缺必填槽且本句填上"才算回话 | 一刀切会重开"先问候再乱打"的乱答洞 |
| 门槛偏保守还是偏严？ | 保守（宁放行不误杀） | 误杀业务代价 > 混入噪声代价；澄清是可恢复的 |
| LLM 做最终兜底吗？ | 否无脑兜；是"模糊带宽"才兜 | 无脑兜贵且不稳（OOD 过自信）；分类兜底（已有）+决策仲裁（L5 新增）双轨，结论仍以证据链为准 |

## 6. 验证方式

- **单元**：`test_golden_eval.py` 新增 rephrase/context 层用例（P0/P1/P2 各批）。
- **回归断言**：`4444@卡号语境` 不返回 `CLARIFY_RESPONSE`；`hjfw@有前文` 仍返回澄清；`22元@无前文` 走槽位/确认。
- **线上灰度**：P0 先"记但不拦"，用 `decision_log` 对账误伤率后再打开拦截。
- **性能**：`InputGate` 为确定性算子（正则/惊讶度表/槽位读 Redis），目标 <10ms；energy 在既有 BERT 推理内算，无额外模型加载。
